# Security Policy

## Supported versions

Security fixes are made against the latest tagged release and the current
default branch.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
private vulnerability-reporting form when it is available, or email
adam.benenson@gmail.com with the subject `Legitimacy security report`.

Include the affected version or commit, the smallest reproduction you can
provide, the expected and observed behavior, and any known impact. Reports may
cover the Rust executable surface, parsers and extractors, certificate or
provenance handling, release artifacts, or a mismatch between a published
formal claim and the code that is asserted to establish it.

Ordinary feature requests and non-sensitive defects belong in the public issue
tracker after release. If disclosure could help someone bypass a governance
check, report it privately first.
